Troubleshooting and Debugging a Broken Pod (12 Minutes)
A developer pushed a broken Pod configuration that needs to be quickly fixed.

Ensure you are working in the default namespace.

Create a Pod named broken-app using the image busybox with the following incorrect command definition: command: ["/bin/sh", "-c", "sleep 3600", "this-extra-arg"]. (This is a common YAML formatting error).

Troubleshoot:

Check the Pod status and identify the failure state (it will likely be in CrashLoopBackOff or Error).

Use kubectl describe or kubectl logs to find the specific error message indicating the command failed to execute.

Action: Fix the Pod configuration by removing the incorrect extra argument ("this-extra-arg") and re-apply or delete/recreate the Pod to get it into the Running state.

Verification: Confirm the broken-app Pod is in the Running state.
